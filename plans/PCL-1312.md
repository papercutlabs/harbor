# Harbor: faithful messages and useful conversation actions

## What we want, and how we will know it is real

Teren uses Harbor to talk with Doug while Desk shares a narrow terminal. That conversation carries decisions, instructions and commands. If formatting disappears or an answer loses the message it refers to, Teren has to reconstruct the meaning or return to another application. This work removes that repeated effort and supports PcL's aim of carrying more useful responsibility without requiring a principal to carry its internal details.

Teren reported broken formatting in a screenshot and asked for a comparison with Telegram's app source. After receiving six concrete proposals, Teren accepted all six: faithful rich text, direct code copying, reply navigation, search within the conversation, reaction choice, and better links with pinned-message navigation. The source of that expansion is https://t.me/c/3526758589/2822/10014 . It replaces the earlier code-repair-only completion boundary. Each accepted capability remains part of done.

## Why the existing path does not do this

Harbor already has an actual Telegram backend, media, drafts, replies, editing, forwarding, mouse selection and a compact Commands menu. Those remain the foundation. The backend converts native formatted text to a Markdown-like string and discards remaining formatting ranges. Harbor then guesses the ranges from that string. Actual offline TDLib execution reproduced the screenshot: the producer closes a code block immediately after its content, while Harbor requires a newline first. The same loss of entity metadata removes native quotes and underlines.

The existing protocol also declares message search, pinned-message lookup and available reactions. Their presence is not proof of full behavior: the current Telegram FindMessageRequest delegates to the local message cache. A search of only cached text cannot establish that a conversation contains no other match. The implementation must reuse the existing request/event path where it works and add the missing server-backed behavior where required, preserving the older caller's semantics.

## The smallest shape that works

Keep one native Harbor application and the existing Telegram connection. Preserve native text and its formatting ranges through the current message path, including cache reload; do not add another service or another parser that tries to reconstruct missing information. Retain the existing fallback only for old cached or demo messages whose native ranges are unavailable. A native message with zero formatting ranges must still remain literal text.

Put the new actions in the existing selected-message menu and Commands menu. A code block, link or reaction with several choices gets a small transient chooser. A reply opens its original and offers a return action. Search and pinned messages reuse the conversation's message navigation. The cheaper shape of printing more text or exposing raw identifiers cannot provide these actions, and permanent toolbars would consume the space this work is meant to protect.

The formatting and conversation actions share message identity, selection, menu handling and reading-position state. One builder keeps that connected behavior together, starting from the existing code/copy correction already in progress. The lead integrates the actual result and commissions one connected review. Splitting edits to the same message loop across several builders would add coordination and conflicting changes without independent work to justify it.

## What failure costs, and how much care that buys

A formatting error can alter a copied command or the apparent meaning of an instruction on every read. A navigation error can lose a draft, move the user to the wrong conversation or react to the wrong message. Native offline regressions, one independent code review and the repository's normal checks earn their cost. Cached message history can be fetched again, but drafts are unique: schema changes must be additive and must not delete existing data or rewrite draft storage. An old binary remains the ordinary code rollback; no live profile is mutated during development.

The fastest sound shape is to reuse the existing backend, build all coupled actions in one isolated contribution, and qualify them using synthetic Telegram objects and a disposable real terminal. No account enrollment, new subscription, external recipient or live seat operation is needed. Routine release goes through the existing Harbor build and Office pin/update path. Consumer confirmation is about the actual laptop result and does not gate source work.
